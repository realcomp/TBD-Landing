# План: уведомления админу о регистрации и подтверждении email

## Контекст

Текущий waitlist-флоу не меняется. Пользователь регистрируется на лендинге →
получает письмо со ссылкой подтверждения email → кликает → статус меняется
на `confirmed`. Это всё уже работает (`server/routes/waitlist.ts`,
`server/lib/email-template.ts`, `server/lib/email-translations.ts`, Resend).

Цель этого плана — добавить администратору (`real310@gmail.com`) email-уведомления
о двух событиях, без изменения пользовательского флоу, без новых страниц,
без кнопок/токенов подтверждения на стороне админа.

## 1. Функция отправки админ-уведомлений

- Новый файл `server/lib/admin-notifications.ts`
- Использует существующий Resend-клиент (`server/lib/resend.ts`) и FROM_EMAIL
- Два варианта текста письма: "Новая регистрация" и "Email подтверждён"
- Получатель — через новую env-переменную `ADMIN_NOTIFICATION_EMAIL`
  (по умолчанию `real310@gmail.com`), чтобы не хардкодить адрес в коде

## 2. Хук на регистрацию

- В `server/routes/waitlist.ts`, в `handleWaitlist`, в ветке "новый email"
  (Case A) — после создания записи `pending` и отправки письма пользователю —
  дополнительно вызвать уведомление админу: email, дата, язык, IP/UA
- Повторные попытки/resend (Case C, токен старше 12ч) уведомление не
  триггерят — только первая регистрация

## 3. Хук на подтверждение

- В `handleConfirm` (`server/routes/waitlist.ts`, строки ~102-138) — после
  успешного обновления статуса на `confirmed` — отправить админу
  уведомление: email, дата подтверждения

## 4. Отказоустойчивость

- Отправка уведомления админу оборачивается в try/catch и не должна ронять
  основной запрос пользователя, если Resend временно недоступен (просто лог
  ошибки)

## 5. Редирект после подтверждения

- В `handleConfirm` (`server/routes/waitlist.ts:133`) сменить редирект с `/`
  на `https://dtg.sportomatics.com/login?redirect=%2Finbox`
- `/login` и `/inbox` — часть отдельного приложения, на которое уже ведёт
  ссылка в `client/components/sections/Access.tsx:43`; страница логина не
  входит в скоуп этого плана, просто меняем целевой URL редиректа

## 6. Не требуется на этом этапе

- Изменений схемы Supabase
- Новых страниц/роутов (страницы логина/регистрации не нужны)
- Токенов/защиты ссылок — кнопка "подтвердить пользователя" в письме админу
  не нужна, шаг одобрения админом убран из скоупа

## 7. Проверка

- Локально прогнать регистрацию тестовым email → проверить, что пришло
  письмо пользователю + письмо админу
- Кликнуть по ссылке подтверждения → проверить второе письмо админу и
  редирект на `https://dtg.sportomatics.com/login?redirect=%2Finbox`

## Затрагиваемые файлы

- `server/lib/admin-notifications.ts` (новый)
- `server/routes/waitlist.ts` (два хука уведомлений + смена редиректа в
  `handleConfirm`)
- env: добавить `ADMIN_NOTIFICATION_EMAIL`
